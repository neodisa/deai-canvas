# jira-tracker

Вбудований модуль ролі `tracker`: показує статуси задач із **Jira Cloud**. Ядро питає модуль про ключі задач простору
(`DEMO-1`, `DEMO-2`…), а модуль повертає назву статусу й його категорію (нова / у роботі / готово). Статус видно на екрані
«Задачі», а в просторі з командним дашбордом — ще й на картках команди.

Модуль лише читає: нічого не створює й не змінює в Jira. Підтримується лише Jira Cloud; Jira Server / Data Center —
окремий модуль пізніше.

## Налаштування

| Поле | Що вводити |
|---|---|
| `base` | Адреса вашого сайту Jira Cloud: `https://<сайт>.atlassian.net` (чи власний домен). Лише https, імʼя хоста (не IP і не `localhost`), без шляху, параметрів і облікових даних. |
| `email` | Пошта вашого облікового запису Atlassian. |
| `token` | API-токен Atlassian (зберігається в `~/.deai/secrets.json`, у сторінки й превʼю не потрапляє). |

Як отримати API-токен: у налаштуваннях облікового запису Atlassian, у розділі безпеки, створіть API-токен і скопіюйте його
одразу — повторно Atlassian його не показує.

## Що відбувається в мережі

- `check` — `GET <base>/rest/api/3/myself`: 200 означає «підключено». Вердикти: налаштування не підходять (адреса, пошта,
  токен) — `module-error`; HTTP 401/403 — `tracker-auth` («Jira не прийняла email чи токен», окремий код: «Підключення» підписує
  `module-error` як збій модуля, а тут хибні облікові дані); Jira недосяжна — `network`; інша відповідь — текст зі статусом HTTP.
- `statuses` — `POST <base>/rest/api/3/search/jql` з запитом `key in (…)` і полем `status`; до 100 ключів за раз, лише ключі
  виду `DEMO-1` (модуль перевіряє їх ще раз: вони йдуть у запит). Тайм-аут сокета — `ctx['timeout_s']` (4 с для екрана
  «Задачі», 15 с для синку дашборда).
- Запити не йдуть за переадресаціями, щоб токен не потрапив на чужий хост.
- У текстах помилок немає токена, пошти й вмісту відповідей Jira — лише фіксовані слова та HTTP-статус; тіло відповіді з
  помилкою не читається взагалі.

## Помилки `statuses`

| Відповідь Jira | Код | Текст |
|---|---|---|
| 401, 403 | `module-error` | невірний email чи токен (HTTP …) |
| 3xx | `module-error` | Jira відповіла переадресацією: за нею не йдемо — перевірте адресу сайту |
| 400 | `module-error` | Jira відхилила запит (HTTP 400): перевірте ключі задач |
| 408, 429 | `tracker-error` | Jira відповіла HTTP … |
| інші 4xx | `module-error` | Jira відповіла HTTP … |
| 5xx, мережа, тайм-аут, відповідь не тієї форми | `tracker-error` | Jira відповіла HTTP … / Jira недосяжна (…) |

408 і 429 — тимчасове (таймаут, ліміт запитів): людині нічого виправляти, повтор згодом проходить.

Один невідомий Jira ключ у пакеті (Jira відповідає 400 на весь запит) лишає весь пакет без статусів: виправте ключ задачі.
