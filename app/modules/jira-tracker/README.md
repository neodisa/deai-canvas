# jira-tracker

Вбудований модуль ролі `tracker`: показує статуси задач із **Jira Cloud**. Ядро питає модуль про ключі задач простору
(`DEMO-1`, `DEMO-2`…), а модуль повертає назву статусу й його категорію (нова / у роботі / готово). Статус видно на екрані
«Задачі», а в просторі з командним дашбордом — ще й на картках команди.

Модуль лише читає: нічого не створює й не змінює в Jira. Підтримується лише Jira Cloud; Jira Server / Data Center —
окремий модуль пізніше.

## Налаштування

| Поле | Що вводити |
|---|---|
| `base` | Адреса вашого сайту Jira Cloud: `https://<сайт>.atlassian.net` (чи власний домен). Лише https, імʼя хоста (не IP і не `localhost`), без шляху, параметрів і облікових даних. |
| `email` | Пошта вашого облікового запису Atlassian. |
| `token` | API-токен Atlassian (зберігається в `~/.deai/secrets.json`, у сторінки й превʼю не потрапляє). |

Як отримати API-токен: у налаштуваннях облікового запису Atlassian, у розділі безпеки, створіть API-токен і скопіюйте його
одразу — повторно Atlassian його не показує.

## Що відбувається в мережі

- `check` — `GET <base>/rest/api/3/myself`: 200 означає «підключено»; 401/403 — невірний email чи токен.
- `statuses` — `POST <base>/rest/api/3/search/jql` з запитом `key in (…)` і полем `status`; до 100 ключів за раз.
- Запити не йдуть за переадресаціями, щоб токен не потрапив на чужий хост.
- У текстах помилок немає токена, пошти й вмісту відповідей Jira — лише фіксовані слова та HTTP-статус.

Один невідомий Jira ключ у пакеті (Jira відповідає 400 на весь запит) лишає весь пакет без статусів: виправте ключ задачі.
