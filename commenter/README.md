# Коментатор (commenter)

Шар коментарів, який малює піни на макеті, форму нового коментаря й рядок режимів і працює з обома каналами (локальним і
командним) через сховище, яке йому дає адаптер модуля `comments`. Один вихідний файл — `src/comment-layer.js`, збірка — мінімізований
`comment-layer.min.js` у `app/vendor/`.

## Звідки

Джерело — comment-layer зі старого репозиторію дизайн-офісу, коміт `3581cd0`; перенесене сюди 13.11.2026. Копія в тому репозиторії живе
окремо й далі не синхронізується: **для Deai ця тека — головне джерело**.

## Режим хоста

Без опції `host` коментатор працює як завжди: своя ручка на краю, своя панель, свої клавіші (так він працює в опублікованих
превʼю й у чужих проєктах). З `host` оболонка бере панель на себе:

```js
init({ host: {
  onReady(),            // коментатор готовий
  onChange(snapshot),   // змінився список / стан; snapshot — мілка копія
  onSelect(id),         // користувач вибрав пін
  onMode(on),           // режим коментування увімкнено / вимкнено
  rightInset(),         // скільки пікселів праворуч займає панель оболонки
}})
```

Методи для оболонки: `snapshot()`, `focus(id)`, `carry(id)` (перенести коментар у поточну ітерацію), `editComment(id, text)`,
`openShot(id)`, `togglePins()`; а також наявні `setCommentMode(on)`, `resolveComment(id)`, `reopenComment(id)`, `removeComment(id)`.

Додатково з 0.27.0 (усі необовʼязкові):

```js
init({ audiences: [{ id, label, icon, color, note, private }, …],
       host: { defaultAudience,        // id аудиторії (рядок чи функція) для чипів; не з переліку — перша
               onAudiencePick(id),     // користувач вибрав адресата у формі
               bottomInset() }})       // скільки px знизу займає острівець хоста: форми не лягають під нього
```

- `audiences[i]`: `color` — колір піна за адресатом (`#rgb`…`#rrggbbaa`, інакше колір за замовчуванням); `note` — рядок під
  чипами для вибраної аудиторії; `private: true` — фідбек лишається на цій машині, і лише тоді заголовок розділу потрапляє в
  контекст піна (`meta.ctx.heading`). Без прапора (чи не строге `true`) заголовка в контексті нема: у командному піні він міг би
  містити імена людей.
- **Чипи адресата** є лише з `host` і ≥ 2 аудиторіями, і в звичайній формі, і в формі «Кілька». Без хоста форма як була.
- `tool()` → `{ mode, freeze, armed, modes, canFreeze }`: поточний режим (`element` | `text` | `multi` | `area`), заморозка,
  чи коментування увімкнено, доступні режими (на полотні лише `element`) і чи можна заморожувати.
- `setMode(m)` вибирає режим і вмикає коментування (`false` — недоступний чи невідомий); `setFreeze(on)`.
- `setMeta(id, patch)` змінює поля `meta` піна (`null` прибирає ключ; ключі `__proto__`, `constructor`, `prototype`
  ігноруються).
- `uploadShot(id, dataUrl, comment)` сховища отримує третій аргумент — коментар, щоб комбіноване сховище знало адресата.
- У режимі хоста коментатор не малює власної смужки режимів: режими малює хост (острівець) через `tool()`/`setMode`/`setFreeze`.

Додатково з 0.32.0 (обидва необовʼязкові; без них поведінка та сама, що була):

```js
init({ host: { onAdd(id),        // створено коментар (звичайний, канвасний чи «перенесений»): id — ДО першого onChange
               userName() }})    // хост сам дає імʼя автора (рядок); тоді prompt() НЕ викликається ніколи
```

- `onAdd(id)` лунає в момент створення, ще до першого `onChange` із цим коментарем: так хост (публічне превʼю) записує, що
  коментар «мій» — створений у цьому браузері.
- `userName()`: порядок імені — `opts.user` → `localStorage['comment-layer:user']` → `host.userName()` → `opts.defaultUser` →
  «Anonymous». З цим гачком `prompt()` у ланцюжку нема взагалі, а порожнє імʼя («Anonymous») НЕ записується в localStorage —
  оболонка може спитати ще раз. Хост без гачка (Deai) — як раніше: `prompt()` останнім, а імʼя запамʼятовується.

У режимі хоста: ручка й панель коментатора сховані; на клавіатуру він слухає лише Escape у власному вікні; ігнорує клавіші з полів
поза своїм shadow root; `destroy()` не викликає жодних колбеків (тож панель оболонки не закривається при зміні каналу).

## Збірка й штамп

```bash
cd commenter && npm ci && npm run build
```

Збірка пише прямо в `app/vendor/` і в `commenter/build-stamp.json` (хеш джерела, версія esbuild, хеші виходів). Вихід
детермінований: повторна збірка не дає різниці в `git diff`.

## Охоронець

`tests/commenter-stamp.test.mjs` падає, якщо джерело й зібраний файл розійшлися зі штампом — тобто джерело змінили без перезбирання.
Тести самого коментатора: `node --test commenter/test/*.test.mjs`.
