# Знімки пінів: якість і пропуски

Статус: чернетка 23.11.2026, рівень «середній» (спільний код коментатора → одне ревʼю в кінці й повний релізний прогін).
Основа — гілка «Відповіді в коментарях» (0.35.0), бо вона вже змінила код знімка (`meta.shotMiss`, обрізка SVG, `shotLib`).

## Навіщо

Власник 23.11.2026, два баги коментатора:

1. Знімок кожного піна малий і поганої якості — «з ними неможливо працювати».
2. Знімки знімаються не на кожній сторінці: то є, то нема.

Чернетка черги фідбеку 20.11 (живий продукт, 19 з 39 пінів без знімка) — ймовірно, та сама причина, що й у п. 2.

## Докази (стенд)

Копії справжніх макетів (5 задач, 60 сторінок) у пісочниці, справжній `html2canvas` 1.4.1 і бандл коментатора, по 12 кліків
на сторінку в різних точках екрана — як людина. Скрипти стенда — у scratchpad сесії, не в репо.

**Баг 2.** 718 пінів: зі знімком 89 %; на 19 сторінках із 60 хоч один пін без знімка. Причини 82 пропусків:

| Скільки | `shotMiss` | Помилка `html2canvas` |
|--:|---|---|
| 71 | `render` | `Attempting to parse an unsupported color function "color"` / `"oklab"` |
| 9 | `render` | `Unable to find element in cloned iframe` |
| 2 | `too-big` | — (ціль понад 1500 вузлів) |

Третя причина знайшлась на останньому пропуску (1 з 718): у клоні `html2canvas` ще йдуть CSS-переходи (таблиці стилів клону
довантажуються, і `transition` стартує від стилів за замовчуванням). Колір посеред переходу обчислюється в `oklab(…)`, а перехід
у каскаді сильніший за inline `!important` — переписаний колір не діє. Ще й знімок ловить проміжний колір.

- **Кольори.** `html2canvas` 1.4.1 розбирає лише `rgb/rgba/hsl/hsla`. Браузер віддає обчислений колір у тому просторі, у
  якому його задано: `color-mix(in srgb, …)` → `color(srgb …)`, `color-mix(in oklab, …)` → `oklab(…)`, `oklch(…)` → `oklch(…)`.
  Досить одного такого кольору в цілі, її нащадках (тіні, градієнти, рамки) чи фоні `html`/`body` — і рендер кидає. Сторінки,
  де CSS макета не має `color-mix`/`oklch`, знімаються завжди; де має — частина цілей ні. Звідси «то є, то нема».
- **SVG-ціль.** Клік по іконці дає ціль `svg`/`path`. `html2canvas` 1.4.1 запам'ятовує клон цілі лише для HTML-елементів
  (`isHTMLElementNode(clone)`), тож для SVG клону «нема».

## Рішення

### Баг 2

- **Переходи в клоні вимкнено:** першим кроком `onclone` додає в клон стиль `*,*::before,*::after{transition:none!important}`
  (лише переходи; анімації не чіпаємо — `animation: none` сховав би елементи з `fill-mode: forwards`).
- **Кольори — у клоні, не на живій сторінці.** В `onclone` (уже є: фіксує бокс цілі) — обхід `html`, `body`, цілі й нащадків
  клону (разом із вузлами-замінниками псевдоелементів). Для колірних властивостей (`color`, `background-color`,
  `background-image`, чотири `border-*-color`, `outline-color`, `text-decoration-color`, `box-shadow`, `text-shadow`,
  `-webkit-text-stroke-color`, `-webkit-text-fill-color`, `caret-color`, `column-rule-color`) значення з функціями
  `color()`, `color-mix()`, `oklab()`, `oklch()`, `lab()`, `lch()` переписуються в `rgba()`. Перетворення — сам браузер: колір
  малюється в canvas 1×1 і читається піксель (кеш на значення). Спершу всі читання, потім усі записи (`!important` inline у
  клоні) — без перерахунку стилів на кожен запис.
- **SVG-ціль → найближчий HTML-предок** (іконка в кнопці → кнопка). Лише для знімка; якір, відбиток і HTML піна — як були.
- `too-big` — без змін (2 % пропусків, ліміт тримає 0.30.1 від фризу).
- Коди `shotMiss` не змінюються.

**Критерій.** Той самий стенд: ≥ 98 % пінів зі знімком, жодного `render` через колір чи SVG. Прототип усіх трьох виправлень
(обгорткою над `html2canvas` у стенді): кольори + SVG — 715 з 718 (2 `too-big`, 1 — перехід); з вимкненими переходами та
сторінка — 12 з 12.

### Баг 1

**Чому малі.** `_captureShot` рендерить у масштабі 1 (на Retina — удвічі менше пікселів, ніж на екрані), стискає до 360 px
завширшки й JPEG 0.6. Секція 1440 px стає смужкою 360×85; лайтбокс показує ті самі 360 px. Обмеження стоїть від перенесення
коментатора (`comment-layer`), не від 0.30.1. Знімок лежить inline у `meta.shot` — у рядку Supabase (75 % читання каналу,
урок квоти трафіку 21.10) і в `.dc-local-comments.json` (у 7 задачах він уже в історії git макета).

**Вимірювання** (25 сторінок, 253 знімки, Retina-екран, справжній `html2canvas`):

| Варіант | Розмір | KB середнє / p90 |
|---|---|--:|
| зараз | ×1, ≤ 360 px, JPEG 0.6 | 7.5 / 16 |
| мініатюра | ×2, ≤ 720 px, JPEG 0.7 | 23 / 47 |
| повний | ×2, ≤ 2400 px, JPEG 0.85 | 118 / 180 |

Рендер ×2: медіана та сама (67 проти 66 мс), p90 191 проти 141 мс; але на гігантських цілях (сторінка 1200×15651) найдовша
задача 1.1 с проти 0.3 с. Тому масштаб ×2 — лише до стелі пікселів полотна (≈ 6 Мп): великі цілі рендеряться як зараз.

**Варіанти для власника:**

- **A.** Один більший inline-знімок (×2, ≤ 1600 px). Просто, але inline ×11: рядки Supabase, кеш сесії, локальний файл.
- **B (рекомендований).** Два розміри: inline-мініатюра ≤ 720 px (×3 байтів) для картки; повний ≤ 2400 px — окремим файлом:
  командні — у Storage, як зараз (`meta.shotUrl`), локальні — файлом поруч із задачею (не в git). Лайтбокс відкриває повний.
- **C.** Лише мініатюра ≤ 720 px inline. Картка чітка, лайтбокс удвічі більший за теперішній, широкі секції — усе ще дрібні.

**Рішення власника 23.11.2026: B; випуск — 0.35.1** (латка поверх «Відповідей»).

**B докладно:**

- **Рендер:** масштаб `min(devicePixelRatio, 2)`, але полотно ≤ 6 Мп (`SHOT_MAX_PX`): більша ціль — менший масштаб (до ×1 і
  нижче). Ліміти вузлів і SVG (0.30.1) — як були.
- **Мініатюра** (`meta.shot`, inline): вписана в 720×720, JPEG 0.7. Картки (панель Deai, панель коментатора) — як зараз.
- **Повний** (вписаний у 2400×2400, JPEG 0.85, кодування `toBlob` — поза головним потоком) іде в `uploadShot` замість
  мініатюри → `meta.shotUrl`. Нема сховища чи заливка не вдалась — лишається мініатюра, як зараз (`upload`).
- **Локальні піни:** `local-adapter.js` отримує `uploadShot` → `POST /api/local-shots` → файл `.dc-local-shots/<id>.jpg` у
  теці задачі (правило в `TASK_IGNORE` — у git макета не їде), `GET /api/local-shots/<id>.jpg`. `dual-store.js` шле
  локальні піни в локальний `uploadShot`, командні — у командний.
- **Лайтбокс** (клік по мініатюрі в картці коментатора й `openShot` оболонки) відкриває `meta.shotUrl`, якщо є, інакше
  `meta.shot`. Старі піни: `shotUrl` = та сама мала картинка — нічого не ламається.
- **Картка Teams** бере `meta.shotUrl` — тепер повний знімок.
