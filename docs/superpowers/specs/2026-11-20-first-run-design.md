# Етап «Перший запуск» (0.33.0)

Дата: 20.11.2026. Статус: прототип погоджено власником 20.11.2026 («Да, пиши спеку»), версія 3 —
https://claude.ai/artifact/Hwk7p3UmqVfHAxRXRsYHnZ (сценарії: Привітання · Агент у терміналі · Огляд без знімків · AGENTS.md ·
Модулі · Меню публікації · ⌘K · Знайомство). Рівень строгості — середній: один фінальний ревʼюер і перевірка проти живого
канваса на релізі; кожна нова перевірка доводиться мутацією.

## Навіщо

Фідбек власника 19.11: «окремо онбординг-сетап — флоу, щоб користувач міг встановити канвас, покроково, і розповісти йому
про функціонал». 20.11: «щоб одним промптом сразу предложила все автоматически настроить через AI, не проходити інтерфейсні
штуки»; «пароль за замовчуванням на всі зовнішні превʼю» (він уже є секретом модуля публікації, але його не знайти).

Шлях нової людини 20.11 пройдено на чистому канвасі (тимчасовий `HOME`). Де він ламається:

1. **README веде не туди.** «Quick start» каже `cp tasks.example.json tasks.json` — це створює старий простір `legacy` з
   неіснуючими шляхами замість привітання. Справжнє встановлення (`git clone` + `ops/canvas-app/install.sh`) сховане в розділі
   «Feedback and updates». Версія в розділі Status — 0.31.0.
2. **«Огляд» не працює з коробки.** Потрібні Node і `npm install && npx playwright install chromium`; цього не робить ні
   `install.sh`, ні `start.command`. «Зняти кадри» показує сирий дамп Playwright («Executable doesn't exist…»).
3. **`install.sh` не перевіряє Node, Playwright і Chrome** і не відкриває канвас.
4. **Ніхто не каже, як підключити агента.** Після майстра — порожня сторінка «Нова ітерація — почни проєктувати»; крок 4
   майстра каже «скажіть агенту в терміналі», але не де його запускати.
5. **Claude Code може не прочитати `AGENTS.md`.** Перевірено 20.11 на Claude Code 2.1.322: у чистій теці `AGENTS.md`
   читається; якщо вище по теках є будь-який `CLAUDE.md` — НЕ читається; `CLAUDE.md` з рядком `@AGENTS.md` у теці простору —
   читається. Документація Claude Code: `AGENTS.md` напряму — лише з 2.1.277 і лише без `CLAUDE.md` вище.
6. **Статус агента в острівці** приходить лише від серцебиття (`POST /api/claude-status`), яке шле плагін власника.
   У нової людини його нема, і нічого про це не каже.
7. **Пароль превʼю** — лише в шухляді «⋯ → Налаштувати» модуля; ні на картці, ні в меню «Опублікувати» (там — лише для ЛІГИ).
8. **Про можливості в застосунку — одне речення** на привітанні.

## Рішення власника

- Головний шлях — **один промпт агентові**; інтерфейсні кроки (майстер) лишаються запасним шляхом «або без агента».
- Знайомство — **карта робочого місця + цикл роботи + демо-задача** (не підказки поверх живого інтерфейсу).
- **Окремого екрана «Перший запуск» у Налаштуваннях нема**: кожен пункт живе там, де без нього щось не працює
  (принцип «одна дія — одне місце»).
- Пароль превʼю — **один на простір** (як є: секрет модуля публікації), просто видимий.

## Що робимо

### 1. `SETUP.md` — інструкція для агента

Файл у корені репо, англійською (як AGENTS.md, рішення 19.11). Пишемо для агента, а не для людини: короткі кроки, точні
команди й маршрути API, перевірка після кожного кроку. Агент відповідає людині її мовою.

**Правила агентові (на початку файла):**
- Перед установкою системного ПЗ (Xcode Command Line Tools, Node, Homebrew) — спитати людину; `sudo` — лише з її згоди.
- Паролі й токени — лише від людини, лише в полі `secrets` API модулів; не вигадувати, не повторювати у відповідях.
- Не правити файли теки Deai; оновлення — кнопкою в канвасі.
- Канвас уже працює (`GET http://127.0.0.1:8765/api/setup` відповідає) — пропустити кроки клону й старту.

**Кроки:**
1. Перевірити: `git`, `python3` ≥ 3.9, Google Chrome чи Edge, `node` ≥ 20 (не обовʼязковий, але без нього нема знімків
   «Огляду» і входу «Системний Vercel CLI»).
2. Код: `git clone https://github.com/neodisa/deai-canvas.git ~/deai-canvas` (або тека, яку назвала людина). Тека вже є й це
   чекаут Deai — використати як є.
3. Знімки: `npm ci && npx playwright install chromium` у теці Deai. Нема Node — сказати людині й іти далі.
4. Значок і автостарт (macOS): `bash ops/canvas-app/install.sh`, перевірка — `--check`.
5. Старт: `./start.command`; чекати, доки `GET /api/setup` відповість.
6. Перевірка: `GET /api/setup` → `shots.state == "ok"` (інакше назвати людині причину й команду з відповіді).
7. **Одне повідомлення з чотирма питаннями, у кожного типове значення:** назва й тека простору (Особисте,
   `~/deai-work/personal`); куди публікувати превʼю (у теку на цьому компʼютері / свій Vercel); пароль на превʼю, один для всіх
   задач простору (без пароля); git-репозиторій для макетів (пізніше).
8. Простір: `POST /api/space-new {name, color, path}` — він сам кладе `AGENTS.md` і `CLAUDE.md` (розділ 6). Тека вже простір —
   канвас її підхопить (наявна поведінка).
9. Модулі: публікація — `static-publish` чи `vercel-publish` через `module-enable`/`module-settings` з паролем у `secrets`;
   git — `git-sync`, якщо людина дала репо; після кожного — `module-check` і назвати результат. Поля кожного модуля —
   з `GET /api/modules?space=<id>`. Токен Vercel людина може вписати сама: Налаштування → Модулі → Vercel.
10. Демо: `POST /api/demo-task {space}` (розділ 5).
11. Відкрити канвас: встановлений значок — `open -a "Design Canvas"`, інакше `open http://localhost:8765/app/`.
12. **Останнє повідомлення** людині: що зроблено й чого ні (з причиною); що де в канвасі (5–6 рядків: вкладки, смуга,
    дерево, острівець з коментарями C та інспектором I, ⌘K); як працювати далі — `cd <тека простору> && claude` і фрази на
    кшталт «зроби екран оплати», «відпрацюй коментарі»; ⌘K «Знайомство з канвасом», якщо щось забудеться.

**Розділ «Статус агента»:** що острівець показує стан агента лише за серцебиттям `POST /api/claude-status` (контракт полів),
що без нього все інше працює, і що ставити хуки в Claude Code людини — лише якщо вона попросить.

**Охоронець:** тест звіряє кожен маршрут `/api/…` із `SETUP.md` з маршрутами `serve.py` — інструкція не сміє посилатися на
неіснуюче.

### 2. Промпти

- **README, до встановлення** (англійською й українською, поряд):
  `Install Deai Canvas: clone https://github.com/neodisa/deai-canvas.git into ~/deai-canvas and follow ~/deai-canvas/SETUP.md.`
  `Встанови Deai Canvas: склонуй https://github.com/neodisa/deai-canvas.git у ~/deai-canvas і зроби все за ~/deai-canvas/SETUP.md.`
- **Привітання, канвас уже працює** (мовою інтерфейсу): `Налаштуй Deai Canvas на цьому компʼютері за інструкцією <setup>.
  Канвас уже працює: <origin>` — `<setup>` = абсолютний `paths.setup` з `/api/setup`, `<origin>` = `location.origin`.
  `/api/setup` не відповів — та сама фраза з «SETUP.md у теці, де встановлено Deai Canvas» замість шляху.

### 3. `GET /api/setup`

```
{ "ok": true, "version": "0.33.0", "python": "3.9.6", "platform": "darwin",
  "paths": { "deai": "<корінь установки>", "setup": "<корінь>/SETUP.md" },
  "shots": { "state": "ok" | "no-node" | "no-playwright" | "no-browser" | "unknown",
             "node": "22.11.0" | null,
             "command": "cd <корінь> && npm install && npx playwright install chromium" | null } }
```

- `no-node` — `_node_bin('node')` не знайшов; `command: null` (текст у UI називає Node 20+). Змінна `DEAI_SHOTS_NODE`
  (абсолютний шлях) підміняє `node` для цієї перевірки — для тестів і для машин із нестандартним Node.
- `no-playwright` — у `node_modules` нема пакета `playwright`; `no-browser` — пакет є, а файла
  `chromium.executablePath()` нема. Визначає один виклик `node -e` у корені установки з тайм-аутом 10 с; збій чи тайм-аут →
  `unknown` (UI тоді нічого не показує й не блокує).
- Результат кешується на 30 с; `?fresh=1` обходить кеш. Захист — як в інших GET API (`api-guard`). Відповідь несе абсолютні
  шляхи лише цієї машини (як `/api/agents-md`); у файли вони не пишуться.

### 4. Привітання (просторів ще нема)

Розмітка — прототип, сценарій «Привітання»:
- Лого, заголовок і лід — як зараз.
- Блок **«Налаштувати через агента»**: пояснення в одне речення, промпт (`.prompt`), кнопка «Скопіювати промпт» (тост
  «Промпт скопійовано — вставте його агентові»; буфер недоступний — промпт лишається видимим для ручного копіювання).
- Рядок «або без агента» і кнопки «Створити простір вручну» (майстер, як зараз) та «Відкрити наявну теку простору».
  Рядок «Або скажи агенту: «створи простір…»» прибираємо: його замінює блок.
- Нижче — розділ **«Знайомство»**: карта, легенда, «Цикл роботи» (розділ 5). **Відхилення від прототипу:** рядка
  «Демо-задача» на привітанні нема — просторів ще нема, а мовчки заводити простір під демо — рішення, якого людина не ухвалювала.
  Демо доступне з кроку 4 майстра і з ⌘K.

### 5. Знайомство й демо-задача

**⌘K «Знайомство з канвасом»** — новий пункт палітри (група налаштувань, поряд із «Баг / ідея»), доступний скрізь. Відкриває
картку в системі діалогів оболонки (`.cv-ask-scrim` + `.cv-ask`, ширша — до 940 px): заголовок, «Закрити», карта з легендою,
«Цикл роботи», рядок «Демо-задача» з кнопкою «Відкрити демо». Esc і клік поза карткою закривають; фокус — у картці, після
закриття вертається туди, звідки відкрили.

**Карта** — схема робочого місця з HTML/CSS (без картинок), позначки 1–7, `aria-hidden`; зміст для читача екрана — легенда
(`<ol>`): 1 вкладки задач, 2 ітерація й сторінка, 3 Макет і Огляд (+ Флоу), 4 Опублікувати, 5 сторінки, 6 пін,
7 острівець (C, I, баг/ідея; ⌘K). **Цикл роботи** — пʼять карток: Агент робить макет → Ви дивитесь → Ви ставите піни →
Агент відпрацьовує → Ви публікуєте. Тексти — прототип, обидві мови в `i18n.js`.

**Демо-задача «Tally»** — вигаданий застосунок бюджету з README-знімків (англійською, як і там): 5 сторінок і 2 стани,
дерево сторінок, флоу, два локальні піни (відкритий і закритий з поясненням агента).
- Вміст — `app/templates/demo/` у репо: `index.html` (переадресація на першу сторінку — потрібна правилу `from`), теки
  сторінок, `pages.json`, `flow.json`, `comments.json` (піни з готовими відбитками). Джерело одне — `ops/readme-shots/demo-pages.mjs`;
  `node ops/demo-task.mjs` перебудовує шаблон (відбитки пінів рахує в Chromium, тому скрипт — для розробника, не для рантайму).
  Тест звіряє сторінки, `pages.json` і `flow.json` шаблону з виходом генератора.
- `POST /api/demo-task {space, title}` → `{ok, id, space}`: задача `tally-demo` (зайнято на машині — `tally-demo-2`, …) у
  вказаному просторі через той самий `task_new` з `adopt_src` = шаблон; потім піни з `comments.json` у локальний канал задачі
  тим самим записом, що й `/api/local-comments`, з адресою цього сервера в `meta.url`. Задача стає поточною. Відмови — ті
  самі, що в `task-new` з `from`.
- Кнопка «Відкрити демо» (⌘K): у просторі вже є `tally-demo` — відкриває її, інакше створює. Простору нема (привітання) —
  рядка нема.
- **Крок 4 майстра:** третій варіант «Звідки макет» — «Демо-задача (Tally)»; «Створити й відкрити» з ним кличе
  `/api/demo-task`, а поля назви й ідентифікатора вимикаються з причиною поруч.

### 6. AGENTS.md і `CLAUDE.md`

Розділ Налаштування → AGENTS.md, над файлом — `set-rows` з двома рядками (прототип, сценарій «AGENTS.md»):

1. **«Запуск агента»**: пояснення в одне речення, команда `cd <тека простору> && claude` (`cn-code`), «Скопіювати».
2. **«Claude Code»** — стан `CLAUDE.md` теки простору:
   - `ok` (поруч є `CLAUDE.md` з рядком `@AGENTS.md`) — галочка, «Claude Code прочитає AGENTS.md: CLAUDE.md поруч підключає його».
   - `missing` (поруч нема `CLAUDE.md`) — попередження, «Поруч нема CLAUDE.md. Якщо вище по теках є свій CLAUDE.md, Claude Code
     не прочитає AGENTS.md» + «Підключити» (створює `CLAUDE.md` з одним рядком `@AGENTS.md`).
   - `no-import` (є `CLAUDE.md` без імпорту) — попередження, «CLAUDE.md цього простору не підключає AGENTS.md — Claude Code його
     не прочитає» + «Підключити» (дописує `@AGENTS.md` і порожній рядок НА ПОЧАТОК файла; решта — байт у байт).
   - `unreadable` (симлінк, не файл, нема прав) — причина без кнопки.

Сервер: `agents_md.claude_status(dir)` і `agents_md.claude_connect(dir)` (атомарний запис, як `write`: тимчасовий файл,
перевірка «файл не змінився між читанням і заміною»); `GET /api/agents-md` несе `claude: {state, path}`;
`POST /api/agents-md {space, claude: true}` підключає. Імпорт — рядок `@AGENTS.md` чи `@./AGENTS.md` (з пробілами по краях)
будь-де у файлі. **Новий простір** (`space-new`) і кнопка «Створити» AGENTS.md кладуть `CLAUDE.md` лише коли його нема;
наявний `CLAUDE.md` без згоди людини не змінюється ніколи.

### 7. «Огляд» без знімків

Блок «Кадри для огляду» лівої панелі (`shots` у `shell-panel.js`) читає `shots.state` з `/api/setup` (запит — при першому
вході в «Огляд» за сесію; повторний `?fresh=1` — коли вікно знову у фокусі, не частіше разу на 5 с, лише поки стан не `ok`):
- `no-playwright` / `no-browser` — бурштиновий рядок «Для знімків бракує Chromium для Playwright. Виконайте в терміналі:»,
  команда `cn-code` з кнопкою-іконкою «Скопіювати команду», «Зняти кадри» вимкнена (причина — цей рядок, поруч).
- `no-node` — «Для знімків потрібен Node.js 20+ — nodejs.org»; «Зняти кадри» вимкнена.
- `ok` / `unknown` — як зараз.
⌘K «Зняти кадри» вимикається з тією самою причиною. **Сервер:** `/api/shoot`, чия помилка містить «Executable doesn't exist»,
відповідає `{ok:false, code:'no-browser', error}`; діалог помилки знімання тоді каже людську причину й команду замість дампу.

### 8. Пароль превʼю

- **Картка модуля** (Налаштування → Модулі): у постачальника ролі `publish`, чий маніфест має налаштування `password` типу
  `secret`, під назвою — рядок із замком: «Пароль превʼю: задано» · «Змінити» / «не задано» (замок бурштиновий) · «Задати» /
  «невідомо». Посилання відкриває наявну шухляду модуля з фокусом на полі пароля.
- **Меню «Опублікувати»** (смуга задачі): у такому просторі — пункт «Пароль превʼю» з підписом «задано · один для всіх задач
  простору» / «не задано · …»; веде в Налаштування → Модулі з відкритою шухлядою й фокусом на паролі. Пункт ЛІГИ `pubpw` —
  без змін. Дані — нове поле простору в `/api/spaces`: `publish_password: true | false | null` (нема поля — постачальник
  пароля не має).
- Підказка під полем пароля в шухляді обох модулів публікації: «Один для всіх задач простору.»

- Статус агента в острівці — лише із серцебиттям `POST /api/claude-status`; `SETUP.md` пояснює, але хуків не ставить.
- Промпт README розрахований на `~/deai-canvas`; інша тека — назвіть її агентові.
- Демо-задача — англійською (вміст README-знімків).
- `CLAUDE.md` пишеться в теку простору: у просторі, що живе в git, це новий файл у репозиторії.
- Перевірка Chromium покладається на `playwright.chromium.executablePath()`; інший браузер Playwright не перевіряється.

## Тести (кожна нова перевірка — мутацією: зламати → червоне → повернути → зелене)

- **Python:** `/api/setup` — кожен стан `shots` (`DEAI_SHOTS_NODE` → підроблений `node`-скрипт у тимчасовій теці), кеш і
  `fresh`; `agents_md.claude_status/connect` — чотири стани, дописування на початок байт у байт, відмова на

  задача, дерево, флоу, піни, унікальний id, відмови; `/api/shoot` → `no-browser`; `publish_password` у `/api/spaces`;
  маршрути `SETUP.md` існують у `serve.py`.
- **JS (node --test):** розмітка блока промпта (шлях, запасна фраза), легенда (7) і цикл (5), стани блока кадрів і причина
  в ⌘K, пункт пароля в меню публікації за станом, рядок пароля на картці, пункт ⌘K «Знайомство», генератор демо ==
  шаблон, нові рядки `i18n` в обох мовах.

  `DEAI_SHOTS_NODE` → стан `no-browser` — команда й вимкнена кнопка; AGENTS.md — «Підключити» для `missing` і `no-import`; пароль — посилання на
