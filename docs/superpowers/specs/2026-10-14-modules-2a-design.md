# Модулі — етап 2а: каркас модулів, публікація в теку, токени з CSS

Дата: 14.10.2026 · репо продукту `neodisa/deai-canvas`,
від `v0.1.0` (простори). Напрям — `docs/design/spaces-and-modules.md`.
Рішення власника 14.10.2026: Deai розробляється окремо від інструмента ЛІГА; етап 2 —
у три частини (2а каркас + тека + токени; 2б свій Vercel + свій Supabase; git, дашборд,

`~/.deai/secrets.json`.

## Проблема

Після етапу 1 простір без інтеграцій не може опублікувати жодного превʼю (409), не може
підключити свою дизайн-систему до інспектора, і взагалі нема способу щось «підключити»:
усе, що ходить назовні, — зашитий код ЛІГА за одним прапорцем `integrations`.

## Мета 2а

1. **Каркас модулів**: модуль = тека, роль = інтерфейс, який ядро кличе; вбудовані
   модулі в `app/modules/`, свої — у `<простір>/modules/` (лише довірені); налаштування —
   у `space.json`, секрети — окремо.
2. **`static-publish`** (роль `publish`) — публікація в теку на диску, увімкнена за
   замовчуванням у кожному новому просторі.
3. **`css-tokens`** (роль `tokens`) — токени дизайн-системи з CSS-файла для інспектора.

Поза 2а: свій Vercel, свій Supabase для коментарів (2б); екран «Підключення» (етап 3);
модулі ЛІГА (git, дашборд, трекер, Teams) — пізніше. Зашитий код ЛІГА в продукті НЕ
чіпаємо: він і далі діє лише в перенесеному просторі з `integrations: true`.

## Модель

### Модуль

Тека з двома файлами:

```
<id>/module.json
<id>/server.py
```

`module.json`:

```json
{"api": 1, "id": "static-publish", "name": "Публікація в теку", "version": "1.0.0",
 "roles": ["publish"],
 "settings": [
   {"key": "folder", "type": "path", "label": "Тека для превʼю",
    "default": "{space}/_published", "required": true},
   {"key": "password", "type": "secret", "label": "Пароль превʼю (необовʼязково)"}
 ]}
```

- `id` — `^[a-z0-9][a-z0-9-]{0,39}$`, збігається з назвою теки.
- `roles` — підмножина відомих ролей: `publish`, `tokens` (у 2а; `comments`, `vcs`,
  `tracker`, `dashboard`, `notify` — зарезервовані, модуль із ними завантажується, але
  ядро їх у 2а не кличе).
- `settings[].type`: `text`, `path`, `bool`, `select` (з `options`), `secret`. Значення
  типу `secret` НІКОЛИ не пишуться в `space.json` і не повертаються API (лише `set: true`).
- Підстановки в `default`: `{space}` — тека простору, `{home}` — домівка.

`server.py` — звичайний Python-модуль; ядро кличе функції за роллю:

| Роль | Функція | Контракт |
|---|---|---|
| усі | `check(ctx) -> {"ok": bool, "error"?: str, "detail"?: str}` | швидка перевірка налаштувань (без побічних ефектів) |
| `publish` | `publish(ctx, build_dir, task) -> {"url": str, "path"?: str}` | забрати зібрану теку превʼю й опублікувати |
| `tokens` | `tokens(ctx) -> {"tokens": {name: value}, "source": str}` | токени ДС для інспектора |

`ctx` = `{"space": {id, path}, "settings": {…без секретів…}, "secrets": {…}, "module_dir": …}`.
Виняток у функції модуля — помилка модуля (`module-error` з текстом), а не падіння сервера.

### Де живуть модулі й їх стан

- **Вбудовані** — `app/modules/<id>/`; завантажуються завжди.
- **Свої** — `<тека простору>/modules/<id>/`; завантажуються ЛИШЕ якщо довірені: у
  `<DEAI_HOME>/trust.json` записано `{"<space-id>/<module-id>": "<sha256 вмісту
  module.json + server.py>"}` і хеш збігається з поточними файлами. Змінився код —
  модуль «недовірений», доки не довірять знову. Недовірений модуль видно в каталозі
  (`trusted: false`), але його код не імпортується. Свій модуль з `id` вбудованого —
  відхиляється (`id-taken`).
- **Увімкнення й налаштування** — у `space.json` простору:
  `"modules": {"<id>": {"enabled": true, "settings": {…}}}`. Для простору з
  `legacy: true` модулі теж можна вмикати (його `space.json` у теці простору).
- **Секрети** — `<DEAI_HOME>/secrets.json` (0600):
  `{"<space-id>": {"<module-id>": {"<key>": "<value>"}}}`.
- **Типові модулі нового простору** (`space-new`): `static-publish` увімкнений із
  налаштуваннями за замовчуванням. Перенесений legacy-простір нічого не вмикає сам.

### Роль → постачальник

- `modules.provider(role)` для простору запиту: увімкнений, завантажений, довірений
  модуль із цією роллю; **один на роль** — увімкнути другий для тієї самої ролі → 409
  `role-taken` (спершу вимкни перший).
- Для простору з `integrations: true` роль `publish` без увімкненого модуля = **зашитий
  шлях ЛІГА** (як зараз, Vercel); увімкнений модуль `publish` у такому просторі має
  пріоритет. Інші ролі ЛІГА в 2а не зачіпаються.
- `/api/task` і `/api/spaces` віддають `space.capabilities`: `{"publish": "<module id>" |
  "legacy" | null, "tokens": "<module id>" | null}`. UI ховає/показує зону публікації за
  `capabilities.publish`, а не за `integrations`.

## Публікація

`POST /api/publish` у просторі запиту:

1. Постачальник `publish` = модуль → **збірка превʼю в ядрі** (нова функція
   `build_preview(task, its, …)`, винесена з наявного `_publish`): ті самі сторінки,
   кадри, маніфест, обгортка; **без сніпета командних коментарів** (у 2а коментарів-модуля
   ще нема — локальний коментатор у превʼю не їде); гейт — лише якщо в модулі задано
   пароль (`password`), інакше без гейта. Потім `provider.publish(ctx, build_dir, task)`.
2. Постачальник = `legacy` → наявний шлях ЛІГА без змін.
3. Постачальника нема → 409 `no-publish-module` («підключи модуль публікації»).

Результат модуля пишеться в `iterations.json` як сьогодні (`publish_url`, `published_at`),
плюс `publish_module`.

### `static-publish`

- `publish` копіює зібрану теку в `<folder>/<task-id>/` (атомарно: збірка в тимчасову
  поруч, потім заміна), повертає `url` = `http://<host>/published/<space-id>/<task-id>/`
  і `path`.
- Канвас роздає опубліковане локально: `GET /published/<space-id>/<task-id>/<rel>` —
  статика з теки модуля цього простору (захист від `..`, лише всередині `<folder>`).
- `check`: тека існує або створюється; запис можливий; не всередині теки інструмента і не
  збігається з текою задачі.

## Токени

- Інспектор перестає статично імпортувати `vendor/ds-tokens.js` для звірки простору:
  він питає `GET /api/ds-tokens` (простір запиту). Відповідь `{profile, tokens, source}`
  або `{profile: null}`.
- Постачальник `tokens` = модуль → його `tokens(ctx)`.
- Нема постачальника → `{profile: null}` — інспектор працює без звірки (як сьогодні для
  невідомого профілю, `DS_NONE`). Legacy-простір: наявні профілі з `vendor/ds-tokens.js`
  (у продукті — порожня заглушка) лишаються як були через `?ds=<profile>`.

### `css-tokens`

- Налаштування `file` (`path`, обовʼязкове) — CSS-файл з custom properties.
- `tokens`: розбирає `--name: value;` з усіх `:root` / `:root[data-theme…]` / `html`
  блоків (без `var()`-розгортання в 2а, значення як є), ігнорує коментарі; ліміт розміру
  файла 2 МіБ.
- `check`: файл існує, читається, знайдено ≥1 токен.

## API (простір запиту; машинні маршрути — як `/api/space-*`)

- `GET /api/modules` → `{modules: [{id, name, roles, builtin, trusted, enabled, status,
  settings: [{key, type, label, value?, set?}], error?}]}` (секрети — лише `set`).
- `POST /api/module-enable {id, settings?, secrets?}` → валідація типів, `role-taken` 409,
  `untrusted` 409, `unknown-module` 404; запис `space.json` + `secrets.json`; відповідь —
  результат `check`.
- `POST /api/module-disable {id}`; `POST /api/module-settings {id, settings?, secrets?}`;
  `POST /api/module-check {id}`.
- `GET /api/ds-tokens`.
- CLI `bin/modules.py`: `list`, `trust <space> <id>`, `untrust`, `enable/disable` — для
  агента й до екрана «Підключення» (етап 3).

## Межі

- Код модулів виконується в процесі сервера (довіра = рішення людини); ізоляції нема.
- Свої модулі ролей, яких ядро ще не кличе, завантажуються, але не використовуються.
- Шифрування секретів нема (0600, як `~/.ssh`); Keychain — пізніше.
- Публікація без гейта — це звичайна тека на диску, видна будь-кому з доступом до диска.
- Зашитий код ЛІГА в продукті лишається (видалення — коли модулі ЛІГА готові).

## Перевірка

- `tests/test_modules.py`: маніфест (валідація полів, ролі, типи налаштувань), завантаження
  вбудованих, довіра (хеш, зміна коду → недовірений, `id-taken`), секрети (0600, ніколи в
  `space.json`, API віддає лише `set`), постачальник (один на роль, `role-taken`, legacy),
  виняток модуля → `module-error`.
- `tests/test_publish_module.py`: `build_preview` з гейтом і без, без Supabase-сніпета;
  `static-publish` (атомарна заміна, шлях-захист, роздача `/published/…`), 409
  `no-publish-module`; legacy-шлях без змін (наявні тести публікації зелені).
- `tests/test_css_tokens.py`: розбір CSS (кілька `:root`, коментарі, ліміт), `check`.
- Ізоляція: усі нові тести — тимчасові `HOME`/`DEAI_HOME`; розтяжка мережі з
  `tests/test_integrations_off.py` — у просторі без інтеграцій публікація через
  `static-publish` не робить жодного зовнішнього запиту.
- Живі: новий простір → позначити ітерацію → «Опублікувати» → відкривається
  `/published/<space>/<task>/`; інспектор у просторі з `css-tokens` показує звірку з ДС.
