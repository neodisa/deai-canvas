# Етап 3c: свої модулі простору й діалог довіри

Дата: 22.10.2026 · репо продукту `neodisa/deai-canvas` · реліз **0.7.0**.
Попередні: 2а (каркас модулів, `2026-10-14-modules-2a-design.md`, 0.2.0), 3a «Підключення»
(`2026-10-20-connections-screen-design.md`, 0.5.0), 3b майстер (`2026-10-21-first-run-wizard-design.md`, 0.6.0).
Дизайн-документ напряму — `docs/design/spaces-and-modules.md` («свої модулі… лише після довіри людини: хеш усієї теки, без
симлінків, ключ довіри — реальний шлях»).

Рішення власника (22.10.2026):

- **Довіру дає лише людина в інтерфейсі.** Агент може написати модуль у `<простір>/modules/`, але ввімкнути його не
  зможе, доки людина не натисне «Довіряю».
- **Діалог — зведення й перелік файлів** (з тим, що змінилось від минулої довіри). Перегляду коду в діалозі нема: код
  людина читає у своєму редакторі.
- **Підхід — знімок** (погоджено разом із дизайном): «Довіряю» копіює рівно показані байти в `<DEAI_HOME>/trusted/<хеш>/`,
  і канвас виконує лише знімок. Тека простору — тільки джерело.

## Проблема

Модуль сьогодні — лише вбудований (`app/modules/`). Щоб підключити свій сервіс (Netlify, власний API коментарів,
корпоративний трекер), треба правити ядро продукту. Тека простору вже має місце для своїх модулів (`<простір>/modules/`
у дизайн-документі), але каркас її не читає: модуль — це Python і JavaScript, які виконуються з правами людини, а тека
простору може прийти ззовні — з git, зі спільного диска, від агента.

## Модель довіри

**Від чого захищаємо.** Від коду, що потрапив у теку простору не від людини за цим компʼютером: спільний простір у git
чи на хмарному диску (колега додав модуль чи змінив його), агент, якого текст коментаря намовив щось записати
(коментарі — недовірений вхід агента, README). **Від чого — ні:** від локального агента з shell (він і так працює від
імені людини й може запустити будь-що); від людини, що свідомо довірилась шкідливому коду. Діалог чесно каже, що
довіра означає.

**Довіра — на машині, не в просторі.** Записи — `<DEAI_HOME>/trust.json` (0600, тека 0700, як `secrets.json`). Тека
простору й `space.json` про довіру нічого не знають і заявити її не можуть: склонований простір сам собі не довіряє.
Вмикання модуля (у `space.json`) — рішення простору й спільне для команди; довіра — особиста. Тому «Забрати довіру» НЕ
пише `space.json`, а простір, де колега ввімкнув свій модуль, на новому компʼютері показує «Увімкнено, але не довірено».

**Довіра — до байтів.** Ключ запису — реальний шлях теки модуля (`realpath`); значення — хеш теки й перелік файлів у
мить довіри. Виконується знімок цих байтів, а не тека.

**Стани свого модуля** (поле `trust` у записі `GET /api/modules`):

| `trust` | Що це | Що виконується | Картка |
|---|---|---|---|
| `untrusted` | довіри на цьому компʼютері нема (чи знімок пошкоджено) | нічого | «Потрібна довіра» + «Довіритись…» |
| `trusted` | хеш теки = хеш довіри | знімок | як у вбудованого + позначка «свій» |
| `changed` | тека змінилась від довіри | **попередній знімок** | «Є зміни — довіртесь, щоб застосувати» |
| `refused` | теку не можна довірити (правила нижче) | знімок, якщо був довірений раніше; інакше нічого | причина + без «Довіряю» |

Тека зникла — модуля нема в каталозі: явно ввімкнений стає `missing`, як сьогодні (запис довіри лишається; повернеться
та сама тека — повернеться й довіра).

## Тека свого модуля

**Де.** `<шлях простору>/modules/<id>/`. Модуль — підтека, чиє імʼя проходить `ID_RE` і в якій є `module.json`;
решта підтек (`_drafts`, `README`, тека без маніфесту) мовчки ігнорується. Тека модуля — справжня тека (`lstat`), не
посилання; посилання на її місці — `refused` (`symlink`). Простір без `path` чи з вимкненим шаром просторів (лише
`DC_TASKS_FILE`) своїх модулів не має.

**Примітки замість карток.** Три випадки не дають запису модуля взагалі (id був би неоднозначним чи тека не читається
як набір модулів), а йдуть у масив `notes` відповіді `GET /api/modules` — `[{"folder": "modules/<імʼя>", "code": …}]`;
«Підключення» показують їх рядками під головою сторінки («Теку `modules/css-tokens` пропущено: такий id уже має
вбудований модуль.»):

- `id-taken` — id уже має вбудований модуль (`app/modules` чи `DEAI_EXTRA_MODULES`): вбудований не підмінити теками
  простору, а запис `space.json` з цим id і далі веде до вбудованого;
- `too-many-modules` — своїх модулів у просторі не більше 32 (за абеткою), решта — примітки;
- `modules-link` — сама `modules` є посиланням чи не текою: жодного свого модуля (`folder` — `"modules"`).

**Id.** Імʼя теки = `id` у `module.json` (як у вбудованих). У двох просторах можуть бути свої модулі з тим самим id —
каталоги різні, секрети теж (ключ секретів — `(простір, модуль)`).

**Правила теки** (сканер `module_trust.scan`; порушення — `refused` з причиною й шляхом файла):

- обхід `os.scandir` без переходу за посиланнями, глибина ≤ 8;
- дозволені лише теки й **звичайні файли з `st_nlink == 1`** (`os.lstat`, не `DirEntry.stat`: на Windows там
  `st_nlink` = 0); посилання, жорсткі посилання, FIFO, сокети, пристрої — відмова;
- `.DS_Store` (звичайний файл) пропускається: не в хеші, не в знімку (Finder інакше знімав би довіру переглядом теки);
  решта прихованих файлів рахується;
- ≤ 200 файлів, ≤ 5 МіБ разом; `server.py` ≤ 1 МіБ і файли адаптера (≤ 8, ≤ 512 КіБ) — як сьогодні;
- імена файлів кодуються в UTF-8 (`_encodable`) і не містять керівних символів;
- `module.json` проходить `_check_manifest` (без виконання `server.py`); маніфест, що не пройшов, — `refused` з його
  причиною.

**Хеш теки.** Кожен файл читається один раз (`O_NOFOLLOW`, `fstat` того ж дескриптора — тип і `nlink` перевіряються
на відкритому файлі), sha256 його байтів. Хеш теки — sha256 рядків `"<шлях>\0<розмір>\0<sha256>\n"` за абеткою шляхів
(шлях — відносний, через `/`). Людині показуються перші 12 знаків.

## Знімок і завантаження

**Знімок** — `<DEAI_HOME>/trusted/<хеш>/` (тека 0700, файли 0600). Пишеться з байтів, які щойно хешовано (не з
повторного читання теки), у тимчасову `trusted/.tmp-<випадкове>/` і перейменовується на `<хеш>`; знімок із таким
хешем уже є — лишається (вміст той самий). Знімок пишеться ДО запису довіри: запис ніколи не вказує на теку, якої нема.

**Завантаження.** Каталог простору для довіреного модуля вантажить **знімок** тим самим `_build` (exec у свіжий
`ModuleType`, без `importlib`), `id` — з запису. Перед першим завантаженням (і після зміни відбитків файлів знімка)
знімок пересканується тим самим сканером; хеш ≠ запису — модуль `untrusted` з причиною «snapshot is damaged — trust it
again». `__file__` модуля — у знімку, тож модуль, що читає сусідні файли, читає довірені.

**Без довіри код не виконується взагалі:** маніфест читається як JSON (назва, версія, ролі, налаштування для картки й
діалогу), а `server.py` не відкривається на виконання і адаптер не роздається.

## Каталог простору (ядро)

Новий модуль `app/module_trust.py` — сканер, хеш, порівняння з довіреним, читання/запис `trust.json`, запис і
перевірка знімка, видалення знімка. Без імпорту `serve`; `deai_modules` імпортує його.

`deai_modules.catalog(space=None)`:

- без простору — як сьогодні, лише вбудовані (`app/modules` + `DEAI_EXTRA_MODULES`);
- з простором — вбудовані + свої модулі простору. Обʼєкт `Module` отримує `origin` (`'builtin'` | `'space'`), `trust`
  (`None` у вбудованого), `source` (тека в просторі, для показу) і `trust_error` (причина для `untrusted`/`refused`).
  Свій модуль без довіри — `status='untrusted'`, `error_code='module-untrusted'`, ролі й налаштування — з маніфесту,
  функцій нема (`fn()` → `None`).

Кожне місце, що шукає модуль у межах простору (`effective_state`, `preflight`, `write_module_state`, `validate_settings`,
`write_secrets`, `module_ctx`, `check`, `_provider_for`, `capabilities`, `module_list`, `task_preview_gate`, роздача
адаптера, збірка превʼю), бере `catalog(space)`. Вбудований каталог без простору лишається там, де простору нема.

**Ролі й постачальник — без нових винятків.** Роль тримає лише модуль `status == 'ok'` (`_holders`, `_provider_for`), тож
недовірений модуль роль не тримає. Наслідки — ті самі, що для зламаного модуля, і це навмисно (жодного тихого
перемикання на інший модуль):

- увімкнений недовірений модуль `publish` → `provider` `None` → публікація відмовляє `no-publish-module`; неявний
  `static-publish` не вмикається, бо явний запис простору вже є;
- увімкнений недовірений модуль `comments` → `_enabled_module_is_lost` (модуль є, не `ok`, роль `comments`) →
  `module-error` у будь-якому просторі, як сьогодні для зламаного;
- `tokens` → `None`: інспектор без ДС, картка пояснює чому.

**Вмикання недовіреного** — 409 `module-untrusted` (`preflight` і `write_module_state`, з `replace` теж: ціль `replace`
мусить бути `ok`). Те саме для `refused` без довіреного знімка: вбудований зламаний модуль вмикати можна (він займе роль
і `check` скаже чому), а свій без робочого знімка — ні, бо це недовірений код. Вимикання, налаштування й секрети недовіреного модуля дозволені: вони не виконують його код
(налаштування простору — спільні, людина може задати секрет до довіри). `check` недовіреного — `module-untrusted` 409
(не вердикт).

**Довіра не створює другого постачальника.** Довіра (і нова, і повторна) модулю, ЯВНО ввімкненому в `space.json`, чий
маніфест (новий) оголошує роль, яку вже тримає інший увімкнений модуль, — 409 `role-taken` з іменем того модуля
(«спершу вимкніть …»). Перевірка — на свіжому каталозі ДО запису (best effort; гонку з паралельним вмиканням приймаємо,
як `preflight`).

**`capabilities`.** Ключ кешу додає відбиток своїх модулів простору: відбитки тек `modules/<id>/` (файли — `lstat`) і
відбиток `trust.json`.

**ЛІГА.** Простір з інтеграціями без жодного явно ввімкненого модуля і далі вирішує `publish`/`comments` ДО каталогу
(`'legacy'`), тож свої модулі шлях ЛІГА не зачіпають. У «Підключеннях» ЛІГА свої модулі видно (це основа етапу 4:
інтеграції ЛІГА переїдуть у свої модулі простору ЛІГА).

## Адаптер коментарів свого модуля

Маршрут вбудованого лишається `/api/module-client/<модуль>/<файл>`. Свій модуль — **`/api/module-client/<простір>/<модуль>/<файл>`**
(три складові; `SPACE_ID_RE`): простір — з реєстру, модуль — `catalog(простір)`, `origin == 'space'`, `status == 'ok'`,
роль `comments`, файл зі списку `client`. Роздається з **теки знімка** (`mod.dir`) тим самим `open_module_client`.
Усі відмови — той самий сталий 404. `module_client_urls(prov, space)` будує три складові для свого модуля. Збірка
превʼю (`_read_module_comments`) читає файли адаптера зі знімка — у превʼю потрапляє рівно довірений код.

## API

Обидва маршрути — реєстрові (`_REGISTRY_ROUTES`, точна відповідність), простір — параметр `space` (`_module_space`).

**`GET /api/module-trust?space=<id>&id=<модуль>`** — дані для діалогу, тека сканується заново:

```json
{"ok": true, "trust": {
  "id": "netlify", "name": "Netlify", "version": "1.2", "roles": ["publish"],
  "settings": [{"key": "token", "type": "secret", "label": "Token"}, {"key": "site", "type": "text", "label": "Site id"}],
  "path": "~/work/acme/modules/netlify",
  "state": "untrusted | changed | trusted | refused",
  "refused": {"code": "symlink", "detail": "server.py: symbolic link"},
  "hash": "<64 hex>",
  "files": [{"path": "server.py", "size": 12034, "change": "changed"}],
  "removed": [{"path": "old.js", "size": 300}],
  "total": {"files": 3, "bytes": 14120}
}}
```

`change` — `same` | `changed` | `new` (проти запису довіри; без запису — усі `new`); `removed` — файли запису, яких у
теці вже нема. `refused` і `hash` — взаємовиключні (`refused` → без `hash`). Шлях — з `~` замість домашньої теки.
Відмови: модуля нема серед своїх модулів простору — 404 `unknown-module`; вбудований id — 404 `unknown-module` (довіряти
вбудованому нічого).

**`POST /api/module-trust {space, id, hash}`** — довіра рівно тій версії, яку бачила людина:

1. **Лише з браузера канваса**: заголовок `Origin` є й локальний (`_local_origin`) **і** `Sec-Fetch-Site: same-origin`.
   Інакше 403 `trust-needs-ui` (тіло дочитується). Браузер шле обидва сам; агент через curl за документацією — ні. Це
   охоронець від випадкового чи підказаного виклику, а не межа проти локального агента — README так і каже.
2. Сканування теки; `refused` → 409 `module-refused` з причиною; хеш ≠ `hash` запиту → 409 `module-changed` (діалог
   перечитує дані й показує нову версію).
3. Перевірка «другого постачальника» (вище) → 409 `role-taken`.
4. Знімок (з байтів кроку 2) → запис у `trust.json` під `WRITE_LOCK` (`{id, name, version, hash, files, trusted_at}`,
   атомарно, 0600) → скидання кешів цього модуля.
5. Відповідь `{ok: true, module: <запис GET /api/modules>}`.

**`POST /api/module-untrust {space, id}`** — прибирає запис довіри теки модуля й знімок, якщо на нього більше не
посилається жоден запис. `space.json` не чіпає. Звичайна перевірка `Origin` (як у всіх POST); заголовок
`Sec-Fetch-Site` не потрібен: зняти довіру — безпечний напрям, агент може. Модуля чи запису нема — 404 `unknown-module`
/ `{ok: true}` без змін відповідно. Відповідь `{ok: true, module: <запис>}`.

**`GET /api/modules`** — запис свого модуля: `builtin: false`, `custom: true`, `trust`, `trust_error?`, `source`
(шлях із `~`); `status` — `untrusted` для недовіреного, `error` для `refused` без довіреного знімка, інакше як у
вбудованого (стан знімка). Вбудовані — `custom: false`, без `trust`. Відповідь — `{modules: […], notes: […]}`; `notes`
є завжди (порожній масив, коли приміток нема).

`trust.json` не читається — `trust-unreadable` 409 на `POST /api/module-trust` (не переписуємо зіпсований файл: інакше
мовчки зникли б інші довіри); у каталозі всі свої модулі — `untrusted` з причиною «trust.json is unreadable». Довіра
ніколи не «відкривається» через помилку.

## Помилки

| Код | HTTP | Де | Текст людині (uk) |
|---|---|---|---|
| `module-untrusted` | 409 | вмикання, `check`, заміна | «Модуль не довірено на цьому компʼютері.» |
| `module-changed` | 409 | `POST /api/module-trust` | «Тека модуля змінилась, поки відкритий діалог. Перегляньте ще раз.» |
| `module-refused` | 409 | `POST /api/module-trust` | «Цій теці не можна довіритись: <причина>.» |
| `trust-needs-ui` | 403 | `POST /api/module-trust` | «Довіритись можна лише з канваса на localhost у браузері, що шле `Sec-Fetch-Site` (Safari — від 16.4).» |
| `trust-unreadable` | 409 | `POST /api/module-trust` | «Файл довіри не читається — перевірте `~/.deai/trust.json`.» |
| `role-taken` | 409 | `POST /api/module-trust` | наявний текст «роль уже тримає …» |

Причини `refused` (коди → тексти): `symlink`, `hardlink`, `special-file`, `too-many-files`, `too-big`, `too-deep`,
`bad-name`, `bad-manifest` (з причиною маніфесту). Причини `untrusted`: `snapshot-damaged`, `trust-unreadable`.
Коди приміток: `id-taken`, `too-many-modules`, `modules-link`.

## Екран «Підключення»

Свої модулі стоять у секціях своїх ролей поруч із вбудованими (`groupModules`, за першою роллю; без ролей — «Інше»).
Примітки (`notes`) — рядками під головою сторінки, з іконкою `warn` і текстом за кодом (`cnNote*`).

**Картка** (`connections-model.cardView`, `connections-view.cardHTML`):

- позначка **«свій»** — наявна пігулка `.cn-tag` поруч із «типово», `title` — шлях теки (`source`);
- `cardView` для свого модуля:

  | Стан | `badge` | `actions` | `why` |
  |---|---|---|---|
  | `untrusted`, не ввімкнений | `untrusted` | `["trust"]` | ні |
  | `untrusted`, ввімкнений | `untrusted` | `["trust", "disable"]` | так: «Модуль увімкнено в просторі, але на цьому компʼютері йому не довірено — роль «…» не працює.» |
  | `refused` без довіреного знімка | `error` | `["trustinfo"]` (+ `"disable"`, якщо ввімкнений) | так: причина |
  | `refused` з довіреним знімком | як у вбудованого (стан знімка) | як у вбудованого + `"trustinfo"` | як у вбудованого |
  | `changed` | як у вбудованого (стан знімка) | як у вбудованого + `"trust"` | як у вбудованого |
  | `trusted` | як у вбудованого | як у вбудованого | як у вбудованого |

- новий бейдж `untrusted` — «Потрібна довіра» (іконка `shield`, бурштиновий, як `unchecked`); дії `trust` — «Довіритись…»,
  `trustinfo` — «Чому не можна…»; обидві відкривають діалог довіри;
- рядок довіри під описом (`trustLine(e)` у моделі → ключ словника чи `null`): `changed` — «Є зміни в теці — довіртесь,
  щоб застосувати»; `refused` при працюючому знімку — «Нова версія теки: <причина> — працює попередня».

**Шухляда** (`drawerHTML`): у свого модуля зі станом `trusted`/`changed` у `.cn-dr-foot` — кнопка «Забрати довіру»
(`data-cn-dr="untrust"`, ліворуч, стиль небезпечної дії). Підтвердження — `askYesNo(…, {danger: true})`:
«Забрати довіру до «<назва>»? Його код більше не виконуватиметься на цьому компʼютері.» + для ввімкненого «Роль
«<роль>» не працюватиме, доки ви не довіритесь знову чи не підключите інший модуль.» + «Простір і його налаштування не
зміняться.» Простір запиту фіксується ДО питання (як `connDisable`).

**Рядок для агента** (`agentHTML`) отримує речення: «Агент може написати свій модуль у теці `modules/` простору —
довіритись йому зможете лише ви.»

## Діалог довіри

Модальний, на `askForm` (`app/ask.js`: одинак, Esc, пастка фокуса, `focusBack`), розмітка — `role="dialog"
aria-modal="true" aria-labelledby`, як у діалогах просторів. Чиста функція `trustDialogHTML(d)` у новому
`app/trust-view.js`; усі рядки з диска (назва, версія, шлях, імена файлів, мітки налаштувань) — лише через `esc()`.

Вміст (за погодженим превʼю):

1. Заголовок: «Довіритись модулю «<назва>»?»; для `changed` — «Довіритись новій версії «<назва>»?».
2. `v<версія> · <ролі>`, шлях теки, «Відбиток <12 знаків>».
3. Попередження (рамка `warn`): «Код цього модуля виконується на цьому компʼютері з вашими правами: читає й пише файли,
   ходить у мережу, бачить секрети, які ви йому дасте. Довіряйте лише коду, який ви чи ваша команда переглянули.» Для
   ролі `comments` — ще: «Його JavaScript виконуватиметься в сторінках канваса й в опублікованих превʼю.»
4. «Просить:» — мітки налаштувань, секрети з позначкою «секрет»; нічого — «Налаштувань не просить».
5. «Файли (N, <розмір>)», для `changed` — «змінено від минулої довіри: K»; список (прокрутка, `tabIndex=0`) з
   позначками «новий» / «змінено»; прибрані — окремим рядком «Прибрано: …». Розмір — КБ/МБ з однією цифрою.
6. Кнопки: «Скасувати» (фокус типово) і «Довіряю».

`refused` — той самий діалог без кнопки «Довіряю» і без попередження: «Цій теці не можна довіритись: <причина>.»
+ «Закрити».

**Потік** (`openTrust(entry)` у `app.js`, ним же користується майстер): `GET /api/module-trust` → діалог →
«Довіряю» → `POST /api/module-trust {space, id, hash}` →
- `ok` → діалог закривається, список модулів перечитується (`afterModulesChange`), фокус — на картку;
- `module-changed` → діалог закривається й відкривається знову зі свіжими даними й рядком угорі «Тека змінилась, поки
  діалог був відкритий — перегляньте ще раз»;
- інша відмова → текст помилки в діалозі (`ctl.error`), діалог лишається.

Простір фіксується при відкритті діалогу; агент, що перемкнув простір, діалог не збиває.

## Безпека й межі

- Код свого модуля виконується з правами людини (файли, мережа, його секрети). Пісочниці нема; діалог про це каже.
- Межа «довіряє лише людина» — заголовки браузера, а не криптографія: локальний агент із shell може їх підробити (або
  дописати `trust.json`). Від нього захисту нема й не обіцяємо; від тек, що приходять ззовні, — є.
- Між скануванням і записом знімка байти не перечитуються; між записом довіри й завантаженням знімок перевіряється
  хешем. Сусідні файли, які модуль читає сам, — зі знімка.
- Знімки, чия тека зникла без «Забрати довіру», лишаються в `<DEAI_HOME>/trusted/` (прибирання — поза 0.7.0).
- Windows: права `0600/0700` не виставляються (як у `secrets.json`); жорсткі посилання — через `os.lstat`.
- Довіритись можна лише з канваса, відкритого на `localhost`/`127.0.0.1` (там браузер шле `Sec-Fetch-Site`); Safari
  старший за 16.4 цього заголовка не шле — довіра з нього неможлива (відмова `trust-needs-ui` з поясненням у діалозі).

## Тести

Кожна нова перевірка доводиться мутацією (`python3 -B`, тайм-аут); мутації запускаються з охоронцем памʼяті.

**Python, `tests/test_module_trust.py`** (новий): сканер — кожна причина `refused` окремо (посилання-файл, посилання-тека,
жорстке посилання, FIFO, > 200 файлів, > 5 МіБ, глибина > 8, імʼя з керівним символом, зламаний маніфест), `.DS_Store`
пропущено, інші приховані файли рахуються; хеш стабільний і реагує на вміст, перейменування й новий файл; порівняння
(`same`/`changed`/`new`/`removed`); `trust.json` — 0600, атомарний запис, нечитабельний → помилка й файл НЕ
переписано; знімок пишеться з просканованих байтів (тека змінена між скануванням і записом — у знімку старі байти),
наявний знімок із тим самим хешем не переписується, пошкоджений знімок виявляється; «Забрати довіру» прибирає запис
і лише той знімок, на який більше ніхто не посилається.

**Python, свої модулі в каталозі** (`tests/test_modules_own.py`, новий): `catalog(space)` = вбудовані + свої,
`catalog()` — лише вбудовані; **недовірений код не виконується** — `server.py` пише мітку-файл при завантаженні, і
мітки нема після `GET /api/modules`, `check`, спроби ввімкнути, роздачі адаптера й `capabilities`; довірений виконується
зі знімка (`__file__` у `<DEAI_HOME>/trusted/`); `changed` — далі працює стара версія до повторної довіри; примітки
`id-taken`, `too-many-modules`, `modules-link` (і запису модуля для них нема); вмикання недовіреного (і `replace` на нього) → `module-untrusted`; увімкнений недовірений
`publish` → `provider` `None`, `comments` → `module-error`; довіра, що дала б другого постачальника, → `role-taken`;
ключ `capabilities` реагує на довіру й на зміну теки; простір з інтеграціями без явних модулів вирішує ролі ДО каталогу
(ЛІГА не змінилась).

**Python, API** (`tests/test_modules_api.py`): форма `GET /api/module-trust`; `POST /api/module-trust` без `Origin`,
з чужим `Origin`, з локальним `Origin` без `Sec-Fetch-Site` — 403 `trust-needs-ui`; хеш не той — 409 `module-changed`;
`refused` — 409 `module-refused`; успіх — запис `trusted`; `module-untrust` не чіпає `space.json`; роздача адаптера за
трьома складовими віддає байти знімка, а недовірений модуль, вбудований id у трьох складових і модуль чужого простору —
сталий 404.

**JS, юніт:** `connections-model` (`cardView` для всіх станів таблиці, `trustLine`), `connections-view` (пігулка
«свій», бейдж, дії, кнопка «Забрати довіру» лише в `trusted`/`changed`), `trust-view` (усі рядки з диска екрановані —
імʼя файла `<img onerror>` лишається текстом; позначки змін; режим `refused` без «Довіряю»; `role`/`aria-*`),
`wizard-view` (рядок свого модуля в трьох станах), пробні шпильки проводки (`connAction` → `openTrust`, повторне
відкриття на `module-changed`, підтвердження «Забрати довіру» з простором, зафіксованим до питання), CSS (бейдж і
рядок довіри контрастні AA в обох темах), словник обох мов.

**Живий тест** `tests/live/own-modules.test.mjs`, `PORT_BASE = 13600`, ізольований `DEAI_HOME` і охоронець справжнього
`~/.deai` (`guardRealDeai`). Простір у тимчасовій теці з `modules/memo-own/` (роль `publish`, локальний `check`, як
фікстури «Підключень»; `server.py` пише мітку-файл): картка «свій» + «Потрібна довіра», «Підключити» нема, мітки нема →
діалог (файли, відбиток, попередження) → «Довіряю» → «Підключити» → публікація йде через свій модуль → правка
`server.py` на диску → «Є зміни», у діалозі `server.py` «змінено», а працює стара версія → повторна довіра → нова версія
→ «Забрати довіру» → роль показує помилку, `space.json` не змінився; простір, де модуль уже ввімкнено в `space.json`
(сценарій «колега закомітив»), відкривається з «Увімкнено, але не довірено»; майстер, крок 2: «Довіритись…» у рядку →
рядок стає доступним; `fetch` без заголовків браузера на `POST /api/module-trust` → 403.
