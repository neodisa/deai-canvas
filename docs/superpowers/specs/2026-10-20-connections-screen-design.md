# Етап 3a: екран «Підключення»

Дата: 20.10.2026 · репо продукту `neodisa/deai-canvas` · реліз **0.5.0**.
Попередні: 2a (`2026-10-14-modules-2a-design.md`), 2b-1 (`2026-10-16-vercel-publish-design.md`),
2b-2 (`2026-10-19-comments-role-design.md`). Затверджений прототип — `prototypes/deai-spaces/index.html`
(09.10.2026): з нього береться структура, тексти й поля прототипу не переносяться (там вигадані сервіси).

## Проблема

API модулів готове з 0.2.0 (`GET /api/modules`, `POST /api/module-enable|disable|settings|check`), а інтерфейсу
над ним нема. Людина може підключити свій Vercel, Supabase чи токени дизайн-системи лише командами `curl` або
через агента. Тексти помилок публікації відсилають до екрана «Підключення», якого ще нема.

## Етап 3 цілком (для контексту)

| частина | що | реліз |
|---|---|---|
| **3a** | екран «Підключення» простору — **ця спека** | 0.5.0 |

| 3c | свої модулі з `<простір>/modules/` і діалог довіри | 0.7.0 |

## Мета 0.5.0

- Екран «Підключення» поточного простору: модулі, згруповані за ролями, їхній стан і причина помилки людською
  мовою, підключення, налаштування, перевірка й вимкнення без жодної команди.
- Секрети вводяться в інтерфейсі, але ніколи з нього не читаються: екран знає лише «задано / не задано».
- Заміна модуля в ролі одним кроком («Публікацію зараз робить «Публікація в теку». Замінити на Vercel?»), без
  проміжного стану «роль нічия».
- ЛІГА лишається побайтно такою, як була (охоронець `tests/legacy-golden.test.mjs`).

Поза 0.5.0: майстер (3b), свої модулі й довіра (3c, там же позначка «свій» на картці), вибір теки системним
діалогом, банер «N підключень з помилкою» на екрані «Задачі», іконки й описи з маніфестів.

## Де живе екран

**Сторінка оверлею `#tasks-home`.** Оверлей уже ховає сцену, полотно й панелі (`body.home-open`) і вміє
привітання; тепер він має сторінку: `tasks` (як зараз) або `conn`. Новий оверлей не заводимо: той самий вхід і
вихід (`enterHome`/`leaveHome`), чистий перегляд, палітра в стані `homeOpen`, перечитування при поверненні у
вікно — усе вже є. Майстер 3b стане третьою сторінкою.

**Входи** (усі ведуть на сторінку `conn` поточного простору; дія `conn` у `BAR_ACTIONS`):

1. Дропдаун фішки простору — пункт «Підключення…» (іконка `sliders`) у футері поряд із «Новий простір…» і
   «Назва й колір…». На самій сторінці «Підключення» пункту нема (дія, що нічого не робить).
2. ⌘K — пункт «Підключення простору «<назва>»» у групі `gGo` (`spaceActions`, лише коли є масив `state.spaces`
   і поточний простір). На самій сторінці `conn` пункт не пропонується (дія, що нічого не робить).
3. Голова сторінки «Задачі» — кнопка «Підключення» (`ctl--out`, іконка `sliders`) поряд із «Нова задача», лише в
   просторі без інтеграцій: голова простору ЛІГА лишається як є.
4. Тексти помилок публікації, що зараз кажуть «екран «Підключення» — етап 3» (`publishErrVercelAuth` і коментар
   біля нього в `i18n.js`), кажуть, де екран: «меню простору → Підключення».

**Смуга.** На сторінці `conn` — та сама смуга, що на «Задачах», але плоска крихта «Підключення» (іконка
`sliders`) замість «Задачі». Логотип веде на «Задачі» і тут НЕ підсвічений (`ctl--on`, `aria-current="page"` лише на
«Задачах»: поточну сторінку називає крихта; фінальне ревʼю), кнопка «назад до задачі» — як була.

**Простір.** Сторінка показує той простір, який був поточним на вході. Перемикання простору фішкою, коли сторінка
відкрита, лишає людину на «Підключенні» вже нового простору. Кожен запит сторінки несе явний `space: <id>`: агент
може перемкнути активний простір паралельно, а запис мусить піти туди, що людина бачить.

**Клавіатура.** Клавіші сторінки «Задачі» (`/`, стрілки по картках, Enter) на `conn` не діють. Esc закриває бічну
панель (з незбереженими змінами — спершу питає «Відкинути зміни?»). Вхід на сторінку ставить фокус на першу кнопку
першої картки; закриття панелі вертає фокус на кнопку, що її відкрила.

**Перечитування.** Повернення у вікно (той самий тригер, що `refreshHomeOnReturn`) перечитує список модулів: агент
міг змінити їх через API. Відкрита бічна панель свою форму при цьому не втрачає.

## Склад сторінки

```
Підключення · <назва простору>
Модулі цього простору: куди публікувати, де жити коментарям команди, звідки брати токени.
Налаштування — у <тека простору>/space.json, секрети — окремо, у сховищі Deai на цьому компʼютері.
Без жодного модуля канвас працює.

Публікація                     Зараз: Публікація в теку
  [картка static-publish] [картка vercel-publish]
Командні коментарі             Зараз: нікого — коментарі лише локальні
  [картка supabase-comments]
Токени дизайн-системи          Зараз: нікого — інспектор звіряє без токенів простору
  [картка css-tokens]
Не встановлені на цьому компʼютері      (лише коли такі є)
  [картка missing]

┆ Через агента. Те саме агент робить через API канваса: GET /api/modules?space=<id>,
┆ POST /api/module-enable {space, id, settings, secrets} …
```

- **Секції — за ролями**, а не «Вбудовані / Модулі простору», як у прототипі: своїх модулів до 3c нема, а людина
  думає «де публікувати», а не «звідки модуль». Порядок: `publish`, `comments`, `tokens`, далі інші ролі за
  абеткою (назва ролі з i18n, невідома — її id). Модуль з кількома ролями стоїть у секції першої ролі, а рядок
  ролей на картці перелічує всі.
- **Рядок «Зараз»** — з `capabilities` поточного простору (`/api/spaces`): id модуля → його назва; `'legacy'` →
  «вбудована інтеграція ЛІГА (модуль у цій ролі її перекриє)»; `null` → «нікого» плюс наслідок для ролі
  (публікація: «кнопки публікації в смузі нема»; коментарі: «коментарі лише локальні — для вас і агента»; токени:
  «інспектор звіряє без токенів простору»). `capabilities.error` → «space.json не читається» (див. «Помилки»).
- **Секція «Не встановлені»** — записи `status: missing` (увімкнені в `space.json`, а модуля на машині нема).
- **Блок «Через агента»** — пунктирна рамка внизу, справжні маршрути API з id цього простору (екрановано).

## Картка модуля

Іконка ролі (`publish` → `up`, `comments` → `comment`, `tokens` → `sliders`, інші → `dots`), назва, рядок ролей,
бейдж стану, опис (лише для вбудованих), причина помилки, дії.

| запис | бейдж | дії |
|---|---|---|
| `status: missing` | «Не встановлено» (попередження) | Вимкнути |
| `enabled: false` | «Вимкнено» | Підключити |
| `enabled`, `status: ok` | «Підключено» | Налаштувати · Перевірити · Вимкнути |
| `enabled`, `status: unchecked` | «Не перевірено» | Налаштувати · Перевірити · Вимкнути |
| `enabled`, `status: error` | «Помилка» | Налаштувати · Перевірити · Вимкнути |

- `implicit: true` (неявний `static-publish` у просторі без інтеграцій) — ще й позначка «типово».
- **Причина** (блок `.why`) — лише в увімкненого чи `missing` модуля зі `status: error`/`missing`: людський текст
  коду (`error`) плюс `last_check.detail`, коли є. Вимкнений модуль причини на картці не показує (шум); вона
  зʼявиться в панелі, коли людина спробує його підключити.
- **«Перевірити»** на картці — `POST /api/module-check`, кнопка в стані «Перевіряю…» (вимкнена) до відповіді, далі
  перечитування списку.

## Бічна панель налаштувань

Праворуч, ширина 420 px (вужче за 720 px вікна — на всю ширину), `role="dialog"`, `aria-labelledby` на заголовок.
Голова: іконка ролі, назва, «<ролі> · <простір>», кнопка закриття. Тіло: опис, поля, результат перевірки. Футер:
«Перевірити» (лише в режимі правки) і головна кнопка.

**Два режими:** «Підключити» (з вимкненої картки; головна кнопка «Підключити» → `module-enable`) і «Налаштувати»
(з увімкненої; головна кнопка «Зберегти» → `module-settings`).

**Поля** будуються з `settings[]` запису:

| тип | контрол | значення в формі |
|---|---|---|
| `text` | поле тексту | `value` |
| `path` | поле тексту + підказка «{home} — домашня тека, {space} — тека простору, {space_id} — id простору» | `value` (символьне, з типовим маніфесту) |
| `bool` | прапорець | `value` |
| `select` | список з `options` | `value` |
| `secret` | поле пароля, порожнє + рядок стану | — |

- Підпис поля — з i18n для вбудованих модулів, інакше `label` маніфесту як є. Обовʼязкове поле позначене.
- **Секрет:** стан «задано» / «не задано» / «невідомо — сховище секретів не читається» (`set: true|false|null`),
  замок і текст «зберігається поза текою простору, у сховищі Deai». Поле завжди порожнє: введене — нове значення,
  порожнє — «не міняти». Кнопка «Стерти» (лише для заданого й необовʼязкового) позначає секрет до стирання.
  `autocomplete="new-password"`, `spellcheck="false"`. Після будь-якої відповіді сервера поля паролів очищаються.
- **Обовʼязкові поля** перевіряються до запиту: порожній текст/шлях/список чи незаданий і невведений обовʼязковий
  секрет — помилка під полем, запиту нема.
- **Патч:** у `settings` ідуть лише змінені ключі (очищене необовʼязкове → `null`), у `secrets` — лише введені
  (`"…"`) і позначені до стирання (`null`). Нічого не змінено в режимі правки — головна кнопка вимкнена.
- **«Перевірити»** у футері перевіряє ЗБЕРЕЖЕНЕ (`module-check`), тому при незбережених змінах вимкнена з підказкою
  «Спершу збережіть».

**Відповідь** (`{ok, module, check, replaced?}`):

- `check.ok` → панель закривається, тост «Підключено: <назва>» / «Збережено: <назва>».
- `check.ok === false` → панель лишається, червоний блок: «Збережено, але перевірка не пройшла» + людський текст
  коду + `detail`. Чесно: стан уже записано (так працює API — `module_write` пише до перевірки).
- Відмова HTTP (`{ok:false, code, error}`) → червона помилка форми, текст за кодом плюс текст сервера; нічого не
  збережено.
- Після будь-якої успішної відповіді — «Після змін» нижче.

**Закриття** — хрестик, Esc. З незбереженими змінами — `askYesNo` «Відкинути зміни?».

## Заміна модуля в ролі

Одна роль — один постачальник. Неявний `static-publish` теж тримає `publish`, тож підключення Vercel у новому
просторі зараз відмовляє `409 role-taken`.

**Сервер: `replace` у `module-enable`.** `POST /api/module-enable {…, replace: true}`: під тим самим `WRITE_LOCK`, в
одному записі `space.json`, кожен інший модуль каталогу, що зараз тримає хоч одну з ролей цього (явно ввімкнений
чи неявний `static-publish`), отримує `enabled: false` (його налаштування й секрети лишаються), а цей вмикається.
Відповідь додає `replaced: [id…]` (порожній, коли конфліктів не було). Без `replace` — як зараз (`role-taken`).
`replace` не `bool` → `400 bad-settings`. Пре-перевірка (`preflight`) з `replace` роль не перевіряє. Простір без
постачальника між двома кроками не існує — ні для публікації, що летить паралельно, ні для агента.

**Екран.** Перед `module-enable` екран сам бачить зі списку, хто тримає ролі модуля (`enabled: true`, зокрема
неявний). Є такі — `askYesNo`: «<Роль> зараз виконує «<назва>». Підключити «<нова назва>» замість нього? «<назва>»
вимкнеться, його налаштування лишаться.» Так → запит з `replace: true`; ні → лишаємось у панелі. `409 role-taken`
(гонка з агентом) показується як звичайна відмова.

## Вимкнення

«Вимкнути» → `askYesNo` (небезпечна дія): «Вимкнути «<назва>»? Налаштування й секрети лишаться — підключити можна
знову.» Коли модуль — поточний постачальник ролі, додається наслідок з таблиці рядка «Зараз» (крім ЛІГА: там роль
вернеться до вбудованої інтеграції, і про це рядок «Тоді знову працюватиме вбудована інтеграція ЛІГА»).
→ `module-disable` → «Після змін».

## Після змін

Будь-яка успішна відповідь `module-enable|settings|disable` (і вердикт `check` теж: він міняє `status`)
перечитує список модулів і `/api/spaces` (`capabilities`). Запис, що міняє постачальника чи налаштування, міняє й
те, що бачить задача під оверлеєм: смугу (кнопки публікації), рамку (адаптер коментарів вбудовується в сторінку
при віддачі) й інспектор (токени). Після запису (`enable|settings|disable`) — ЛЕГКИЙ шлях (`afterModulesChange`):
перечитати простори, `render({ keepFrame: homeOpen })` (свіжі `capabilities` → смуга; поки оверлей відкритий, рамку під
ним не чіпаємо; якщо людина встигла піти з оверлея, поки запис летів, виходу вже не буде, а попередній `render()` взяв
старі `capabilities` — тоді рамку оновлює сам цей `render()`). Рамку оновлює сам `render()` при виході з оверлею (він присвоює `frame.src` обраної сторінки) — тоді й
адаптер коментарів, і токени інспектора нові. Окремого `reloadFrame()` після нього НЕМА: ревʼю Task 6–7 показало, що
він перезавантажував СТАРИЙ документ поверх щойно відкритої іншої задачі (404 у рамці). Пер-задачний стан (обрана
ітерація, фільтри «Задач», плашки публікації, пакет тюнера) НЕ скидається. Коментатор «Огляду» (`overviewComments`) тримає
екземпляр за ключем «ітерація | канал» — після запису модулів його інвалідуємо (`invalidate()`), інакше нові піни на
«Огляді» йшли б у сервіс, з якого людина щойно пішла (фінальне ревʼю).

> Відхилення від першої редакції (ревʼю Task 6): спершу тут стояв повний `afterSpaceChange()`. Живий тест показав,
> що він скидає обрану ітерацію (`picked`), фільтри й плашки — людина, що вимкнула модуль і повернулась до задачі,
> бачила іншу ітерацію. Простір при цьому не змінюється, тож скидати пер-просторовий стан нема причини.

**Згода на заміну — свіжа.** Після «так» у питанні «Замінити?» екран перечитує список модулів і порівнює, хто тримає
роль, з тим, про кого питав; змінилось — питає ще раз з новими назвами (вдруге змінилось — відмова «роль уже
зайнята», нічого не пише). Тост після заміни називає вимкнені модулі (`replaced`).

**Панель і дії карток.** Поки панель відкрита: відкриття іншої панелі й вихід з екрана (логотип, «назад до задачі»)
ідуть через «Відкинути зміни?», коли форма брудна; під час запиту панелі — ігноруються. «Вимкнути» на картці модуля,
чия панель відкрита, спершу закриває панель (з тим самим питанням). Фокус у панелі після перемальовки (зайнятість,
результат, мова) вертається на той самий контрол.

**Знімок простору.** Дія, що питає підтвердження («Вимкнути», «Замінити?»), бере id простору ДО питання і після
відповіді перевіряє, що сторінка показує той самий простір; інакше — нічого не пише. Сторінка малює простір
`connState.spaceId`, а не «поточний зараз» (`spacesResp` міг змінитись від дропдауна чи ⌘K без перечитування
сторінки).

## Помилки сторінки

- `GET /api/modules` не вдався → банер з людським текстом і текстом сервера + «Спробувати ще» (той самий
  `bannerHTML`, що на «Задачах»).
- `409 space-json-unreadable` (чи `capabilities.error`) → «Файл space.json цього простору не читається — виправте
  чи видаліть його в <тека>; до того модулі не змінити». Картки не малюються.
- Простору нема (шар вимкнено, привітання) → входів на екран нема.

## Тексти

Усе через `t()` в обох мовах (`UK`, `EN`); жодної кирилиці в літералах `app/**`.

- **Ролі:** назва й одне речення-пояснення для `publish`, `comments`, `tokens`; наслідки «нікого».
- **Вбудовані модулі** (`static-publish`, `vercel-publish`, `supabase-comments`, `css-tokens`): назва, опис,
  підписи полів. Таблиця «id → ключі» — у чистому модулі екрана; маніфести не змінюються.
- **Коди перевірки → людський текст:** ядро — `bad-settings`, `module-error`, `check-timeout`,
  `secrets-unreadable`, `bad-manifest`; модулі — `bad-folder`, `not-writable` (тека), `no-token`, `vercel-auth`,
  `vercel-error` (Vercel), `bad-key`, `no-schema`, `supabase-error` (Supabase), `network` (спільний). Невідомий код
  (зокрема вільний текст `css-tokens`) → «Перевірка не пройшла» + сам текст як деталь.
- **Відмови HTTP:** `role-taken`, `bad-settings`, `unknown-module`, `unknown-space`, `space-json-unreadable`,
  `spaces-off`, `unwritable`; невідома — загальний текст + текст сервера.

## Безпека й приватність

- Значення секрету не повертається сервером і не зʼявляється в DOM поза полем, у яке його вводять; після відповіді
  поле очищається. Секрет — лише в тілі `POST`, ніколи в адресі чи журналі.
- Усе, що прийшло від сервера чи маніфесту (назви, підписи, опції, `error`, `detail`, тека простору), — через `esc()`
  у розмітці або `textContent`. `detail` обрізається до 300 символів.
- Колір простору — лише через `spaceColorToken`.

## Тести

- **Юніти (node):** чистий модуль екрана — групування за ролями й порядок, рядок «Зараз» для id / `legacy` / `null`
  / `error`, бейдж і дії для кожного рядка таблиці картки, `implicit`, причина лише де треба, модель форми (поля з
  `settings[]`, брудність, обовʼязкові, патч `settings`/`secrets` зі стиранням), конфлікт ролей (хто тримає, зокрема
  неявний), текст коду (відомий, невідомий, вільний текст). Розмітка: екранування ворожих назв/підписів/деталей,
  `ico()` лише відомі іконки, кожен клас розмітки має правило CSS, висоти в сітці, лише токени.
- **Проводка:** дія `conn` у `BAR_ACTIONS`, пункт у `ddSpaces` і `spaceActions`, кнопка в голові «Задач» лише без
  інтеграцій.
- **Python:** `replace` — атомарно (один запис файла, обидві зміни), неявний `static-publish` замінюється,
  явний теж, без конфлікту `replaced: []`, не-`bool` → 400, без `replace` — `role-taken` як було, налаштування
  заміненого лишаються, `preflight` з `replace` не відмовляє.
- **ЛІГА:** `tests/legacy-golden.test.mjs` зелений без перезйомки.
- **Живий (Playwright, ізольований `HOME`/`DEAI_HOME`, послідовно):** простір без інтеграцій → дропдаун →
  «Підключення…» → чотири вбудовані картки по секціях, `static-publish` «типово»; `css-tokens` → «Підключити» з
  шляхом до фікстурного CSS → «Підключено»; заміна публікації тестовим модулем `memo-publish` (фікстура з
  локальною перевіркою, окрема тека для `DEAI_EXTRA_MODULES`) → діалог «Замінити?» → `static-publish` «Вимкнено»,
  `memo-publish` «Підключено», `space.json` це підтверджує; вимкнення; секрет: введене значення не зʼявляється ні в
  DOM після збереження, ні у відповіді `GET /api/modules`. **Жодної мережі:** Vercel і Supabase в живому тесті не
  вмикаються (їхній `check` ходить у мережу з процесу сервера).
